# VELA-X Ops Console

> **TRAIN SMARTER. PERFORM BETTER.**
>
> מרכז השליטה הפנימי של VELA-X — ניהול מועדונים, עמדות, מכונות, Sessions, כספים,
> שירות, תחזוקה ו־Earn-Back ממקום אחד.

מערכת עובדת מלאה: מסד נתונים אמיתי, Authentication, RBAC, RLS, CRUD, נתוני Seed,
בדיקות ו־Audit Log.

---

## הפעלה מהירה

```bash
# 1. תלויות
npm install

# 2. משתני סביבה
cp .env.example .env
# ערוך את .env: DATABASE_URL, AUTH_SECRET, DEVICE_KEY_ENCRYPTION_KEY
# ליצירת מפתחות:
#   openssl rand -base64 48   →  AUTH_SECRET
#   openssl rand -base64 32   →  DEVICE_KEY_ENCRYPTION_KEY

# 3. מסד נתונים
createdb velax_ops
npm run db:migrate       # Schema + RLS + טריגרים
npm run db:seed          # נתוני הדגמה

# 4. הרצה
npm run dev              # http://localhost:3210
```

## עקרונות שהמערכת אוכפת

אלה אינן המלצות — הן נאכפות בקוד, ב־Schema ובבדיקות:

1. **גבייה ברוטו ≠ הכנסה ≠ תרומה ≠ רווח.** ארבעה שדות שונים, לעולם לא באותו KPI.
2. **סשן שזוכה במלואו אינו Paid Session** — לא בהכנסות, לא בשעות, לא ב־Retention.
3. **מקסימום שני שחקנים לאימון** — `CHECK` ברמת DB + טריגר, לא רק ב־UI.
4. **אין פעולה כספית ללא Audit Log** — באותה טרנזקציה; כישלון ברישום מבטל את הפעולה.
5. **אין Secrets גלויים** — מפתחות מכשירים מוצפנים ב־AES-256-GCM ואינם ניתנים לצפייה.
6. **Earn-Back אינו נמדד לפי Sessions** — אלא לפי הכנסת המגרש המקושרת והאינקרמנטלית.
7. **שעות וכדורים אינם הוכחת שיפור מקצועי** — כלל מוצרי מפרק 5.4 בתוכנית העסקית.
8. **אין הנחה עסקית קשיחה בקוד** — 60 הגדרות עם תאריך תחולה והיסטוריה.
9. **מדד ללא נתוני מקור מוצג כ"אין נתונים"** ולא כאפס (CAC, LTV, NPS).
10. **Audit Log הוא append-only** — טריגר במסד חוסם UPDATE ו־DELETE.
